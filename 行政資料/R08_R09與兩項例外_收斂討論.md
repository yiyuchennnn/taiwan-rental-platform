日期2026-11-06。**以下為送交使用者確認的具體草案，不是已核准規則。** 避免把「開始處理」誤作每個政策選項均已批准。本次先完成草案及已定欄位API，未新增驗證或帳號生命週期假入口。

## 兩項例外

- D01建議：超容量但伺服器證實接收者正式資產增量恰為0，允許交接。資格、公開／封存空位、管理權、平台限制、72小時、同房源重複及隱私照查；未結算換圖先等待。相同hash或發起者釋放量都不能當接收者已合法持有，容量未知不完成。
- D02建議：受限回收項恢復回限制管理，不占封存且不要求封存空位；一般恢復封存仍需空位。限制解除仍依R04，不自動公開。回收期及不可復活規則不變。
- 已送選擇題。收到明確答覆才將例外寫回01／02為已確認；不提前改交接／恢復程式。

## R08 建議條文

1. 分開Email、聯絡方式、刊登身分及房仲公司／證照的查核；狀態有未申請、待核對、待補、通過、不通過、需重新核對。格式正確不等於聯絡有效，註冊成功也不代表刊登身分已查。
2. 首次發布必需的Email、聯絡與刊登身分查核未過，仍可存草稿，但不發布；收到證明不等於通過。首發建議人工核對必要資料，不承諾自動驗證。
3. 只顯示實際完成且仍有效的分項結果，不宣稱「平台保證房源真實／合法」；公司／證照自行填寫與核對通過不同。付費不購得查核狀態。
4. 待補或不通過須理由、補件入口及申訴；不能要求不必要整份證件，具體可接受證明、查核來源、再核對條件、保存與刪除仍需E05及06／12確認。
5. 既有查核需重新核對時，不因單純排隊直接認定造假；若已確認不再符合必要刊登條件或有安全限制，停止新發布／交接，既有公開處理須依明確失效與風險規則。確切失效期間／是否給補件寬限仍需確認，不任意新增天數。
6. 查核資料由有權限人員查看，結果／理由可通知本人，私有證據不可出現在公開標章；申訴覆核角色與無人力時的待處理明示，不假裝已覆核。

最低驗收預期：未驗Email可存草稿不可首刊；同Email不得自動合併帳號；只填公司名不可獲標章；補件重送不重複案件；付費升級不改查核；拒絕提供非必要證件不誤判濫用；私有資料不出現在公開API；失效與申訴不繞過平台限制。

尚需決定：採用建議方向、三身分各自必要查核證據、失效時既有公開處理。資料保存與合法要求不是工程師自行選數字。

## R09 建議條文

| 情境 | 建議行為 | 與帳務／資料的邊界 |
| --- | --- | --- |
| 本人暫停 | 隱藏房源／文章／品牌，停止新發布及完成交接；保留私人草稿、收藏與必要記錄 | 確認前清楚列示續扣是否仍在；建議暫停與取消續扣分開並提供取消入口，待使用者決定 |
| 平台停權 | 阻止一般管理與公開，保留必要補正、退款、取消續扣及申訴入口 | 停權不自動當退款核准，也不沒收實付款；續扣依既有原文不默默取消 |
| 刪帳申請 | 再驗身分，停止公開，取消未來扣款、顯示結果確認中／完成；30天可撤回 | 支付／交接／案件先列出影響，必要交易證據獨立保存；取消未確認不得顯示已完成 |
| 撤回／恢復 | 先恢復本人私人管理，資料按仍可恢復範圍處理，公開內容逐筆確認 | 不自動復刊、不重新授權續扣、不復活永久刪除資產；按最新額度及資格檢查 |
| 等待交接 | 暫停／停權／刪帳期間不完成，原72小時不延長 | 恢復時仍在有效期才可重檢；不得先移轉所有權再查 |
| 待付款或晚到付款 | 顯示對帳中，不要求重付；不得繞過帳戶限制開通或復刊 | 已收但未提供部分需依C04核對處理；仍可能有未選的其他有效期間，不能一律刪資格 |
| 收藏及文章 | 暫停私人保留、對外停止不應公開內容；撤回仍不還原已永久刪除內容 | 刪帳後收藏等非必要資料的最終清除與備份期限由04／06／12定義，不先假定永久保留 |

最低驗收預期：暫停後晚到發布／交接不完成；停權仍可取消續扣及申訴；刪帳續扣取消失敗顯示待處理而非完成；第30天邊界只有一個有效結果；撤回不公開或扣款；晚到付款不重收；未永久刪除可依規則救回，已永久刪除不復活；訂閱退款不直接清掉案件證據。

尚需決定：本人暫停是否連帶取消未來續扣；其餘既有規則可直接整理，但詳細補件／失效／復權流程仍需逐條驗收。沒有把isActive布林假裝成這整套狀態服務。
