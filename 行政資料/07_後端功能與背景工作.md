# 07 後端功能與背景工作

## 07-01 共通操作與工作規則

- 採PostgreSQL持久Operation／Outbox／Job作首發設計，不先購買另一套佇列。業務事實與待辦在同交易提交；worker分程序可重啟，API不依記憶體定時器保證到期。
- 操作至少區分已受理、準備中、等待外部確認、已提交待後處理、完成、可重試失敗、需人工核對；不同業務有自身細分狀態，不用一個SUCCESS概括付款／開通／清理。
- 領工作短交易鎖claim，可用SKIP LOCKED，記lease、attempt、owner、epoch與下次重試時間；重入／逾時不給另一工作同一副作用。租約過期不等於遠端寫入者停止，未能隔離者待人工核對。
- 可重試錯誤採有界退避及抖動，達上限轉人工待辦並告警，業務未完成不抹掉。不可重試格式／授權／過期直接給可修正結果，不無限重送。
- 同事件／來源／操作key去重；外部結果不明先查原操作，禁止產生新付款／退款意圖。至少一次投遞、業務效果冪等，不宣稱所有外部服務天然exactly-once。

## 07-02 上架與公開修改

1. 準備階段讀本人工作版本，完整檢查R02、查核來源、圖片、地址、隱私與公開預覽；外部定位／安全檢查在交易外，保存對應版本及結果，不接受客戶端勾canPublish。
2. 提交先鎖帳戶及必要來源／刊登／資產，重核session、生命週期、持有人、限制、地區、資格、當前筆數／容量、結果版本及本人確認；時效／版本已變則失敗保留可編內容。
3. 在同交易變來源狀態、六類筆數、首次公開及公開revision，建立安全公開投影與索引／通知待辦；首次時間只新成功公開時記錄，歷史未知不猜。
4. 普通修改整版切換；地址／出租範圍按R04必要下架、撤舊分組／周邊後再核對；純隱私收緊先屏蔽不安全舊版本，再安全恢復。提交後下架／刪除／交接的較新狀態不被晚到結果覆寫。
5. 快取／索引更新失敗不供應撤銷內容；公開讀取有最新安全資格門檻。發布API無法只因排入索引就回「已可公開」。

## 07-03 到期、寬限及保留

- 以可信時間及資格來源定期掃描，並在重要提交前補結算已到期事實；worker延誤不能多給付費工具或重開48h。公開讀取到截止時先停止不應展示內容，不依worker恰好準時。
- 公開／文章各自寬限，原截止不因追加來源到期、付款重試、編輯或撤銷重設。自選保留及固定預選快照依R05，截止按最新合法候選與上限執行。
- 必要轉封存允許超額並保留資料；不因封存滿卡住下架。已出租／受限／刪除不被補位復活，升級不自動全公開。
- 臨時筆數到期獨立計算，未領贈送不倒數；單一路徑排程不讓多等級重疊消耗。排程協調未確認不消耗贈送或宣稱續扣已延後。

## 07-04 金流、資格與退款

| 階段 | 事實／提交 | 失敗保護 |
| --- | --- | --- |
| 建報價／訂單 | 保存同版本價格、精確來源、期間、尾差及下次安排 | 10分鐘／當期到期／來源改變失效需重看 |
| 發起付款 | 一筆付款意圖與明確授權，供應商唯一參照 | 結果不明查原筆，不再叫客戶付 |
| webhook／回查 | 驗簽後持久事件、核對商戶／金額／幣別／訂單 | 重送事件一次業務效果，前端跳轉不開權益 |
| 開權益 | 帳戶鎖內套正確來源及排程、Audit／Outbox | 已扣款失敗補處理或退款，不覆原已購／未選來源 |
| 正式終止 | 本人確認選定來源及時間，鎖應退範圍、停止該段 | 審核延誤不減退，其他資格保留 |
| 發退款 | 先保留可退額及同操作，再交供應商 | 未知先查詢；已退＋處理中不超實付；拒付並行不雙返 |
| 續扣／取消 | 獨立授權狀態及供應商確認 | P02暫停不自動取消；刪帳取消未確認顯示待處理；恢復不重啟已取消 |

報價重算不能加收未授權款；贈送／優惠不退現金。正式終止、退款送出及到帳為不同狀態，人工核對也須可追溯。C06精度及逐來源分配由單一計算服務負責，前端／webhook不可各算一套。

## 07-05 交接

邀請建立不移管理權；接受時跨帳戶按固定順序鎖定，再鎖內容及資產，重核雙方資格、接收者查核／公開或封存選擇、筆數、限制、位置同意與72h。P01僅正式新增bytes確為0才可在超容量接收，未知／未結算換圖不行。

成功時同交易改持有人、聯絡確認、資產帳戶權屬／容量及必要狀態；歷史事件不改名，不交接訂閱／文章／私人詢問。失敗原人持有，不先扣走圖片或永久占接收容量。來源仍有引用不假設空間釋放；歸屬扣量與實體刪除不同事件。

## 07-06 圖片與清理

原圖驗證→受限暫存→實際尺寸bytes→預留／權利重核→提交引用。安全換圖先驗新圖再切換，依靠D釋放者一次一筆；未清舊圖時平台承擔暫存，正式帳本不假減量。使用U0−實際D＋正式N，同步合併其他已提交變動，不以快照覆寫。

- 檔案寫入、nonce／proof與工作狀態要跨程序重啟可核對；過期PENDING不得只因時間到自動刪除。須先確認／隔離舊寫入者、核對來源與所有引用，不能刪完後舊程序又寫回。
- 最後引用移除鎖資產並重核；清理先禁止新引用，確認正式各尺寸刪完才釋容量。檔案存在但不可恢復不是清理失敗可反悔。
- 清理失敗保留新生效圖及待辦，提供人工原因，不要求使用者重傳／升級。清理能力不足不能用無限暫存掩蓋，告警與平台成本見12。

## 07-07 其他背景主線

| 通知 | R15對象及必要性、同事件管道去重；送出不等閱讀／授權；供應商未知結果先查，不能承諾絕無重複Email |

## 07-08 驗收證據

每項需測：同時搶最後額度、重送、鎖／版本改變、外部成功但回應遺失、DB提交前後程序終止、租約過期／舊worker復活、過期回報、清理中再引用、任一方帳戶限制。須能從operation／事件／job／Audit還原結果；沒有這些證據不稱完整上架、可靠排程或容量完成。

## 07-09 操作狀態與成功的判定

| 操作狀態（目標名稱） | 會員可相信的事實 | 後續動作 |
| --- | --- | --- |
| ACCEPTED／PREPARING | 已收件，尚未完成業務提交 | 查原operation；未提交且可安全終止時才可取消 |
| WAITING_EXTERNAL | 等待供應商結果，尚不能確認成功或失敗 | 原參照查詢／對帳，不另建付款或退款 |
| COMMITTED_PENDING_EFFECTS | 業務已提交，索引、通知或清理未全部完成 | 保留提交結果；不重新扣款、不倒回舊圖 |
| COMPLETED | 這個操作所要求的必要效果已完成 | 仍受後來的下架、撤權或退款事件影響 |
| RETRYABLE_FAILURE | 同一操作可重試某階段 | 保存提交點；只重試未完成效果 |
| NEEDS_RECONCILIATION | 不能安全自動判定 | 人工查核，有負責人與原因；不造假成功 |
| REJECTED／CANCELLED | 未提交的請求被拒絕／安全取消 | 不撤銷另一個已成功操作，保留必要結果紀錄 |

重試狀態必須帶phase及committedAt，不能把已提交的換圖／付款呈現成「全部失敗，請重做」。一個訂單可以同時是付款已確認、權益待補開、通知待送；畫面按各事實呈現。已扣款但未開通要形成可追蹤案件，不以背景工作無限重試結案。

## 07-10 內容轉換的提交檢查

| 轉換 | 交易內的關鍵檢查 | 不可發生 |
| --- | --- | --- |
| 草稿／封存→公開 | 本人、revision、地區、查核、完整欄位、安全圖、公開位及正式新增資產量 | 超容量但N=0的既存合法資產被一律當新增上傳拒絕；有位卻跳過必要查核 |
| 公開→封存／已出租 | 最新持有人與內容版本；撤公開投影及群組輸出 | 因封存已滿拒絕必要下架 |
| 非永久刪除→回收 | 本人可執行、影響確認、設30天截止、撤公開 | 誤以移回收代表已清bytes |
| 回收→恢復 | 未過截止；仍有限制則回限制區，否則封存位 | 恢復為公開或重設原首刊時間 |
| 回收→永久刪除 | 本人確認或既定期限；和恢復鎖同一筆 | 邏輯承諾刪除後讓新引用／晚到工作復活 |
| 內容限制／解除 | 有權處置、原因與案件；按04計數 | 解除自動復刊，或把帳戶停權當每筆內容違規 |
| 公開普通修訂 | 原公開版有效、新工作版完整驗證、相依版本未變 | 部分新欄位混舊圖／舊費用公開 |
| 改地址／出租單位 | 先必要下架、撤舊定位分組，重核真實單位 | 把不同實體新房源沿用舊身分及首刊 |
| 隱私收緊 | 先撤不安全出口，保留公開計數，安全版本重建 | 暫時屏蔽就多釋一個公開位 |

所有需要額度的操作在帳戶鎖內結算當下有效資格；文字保存、必要下架與刪除不要求先升級。容量判斷按新增正式bytes，不用「U≥L」覆蓋所有命令。

## 07-11 排程與漏跑補處理

| 觸發 | 時間基準 | 晚到／重複時 |
| --- | --- | --- |
| 方案／臨時額度到期 | 資格已保存的effectiveAt／E | 依原時間結算，不從worker執行時間重算 |
| 公開超額寬限 | 各類GraceEpisode原截止 | 先執行當下合法結果，不補發已失真的「尚有48小時」 |
| 交接邀請到期 | 原邀請＋72小時 | 接受交易直接核對；掃描沒跑也不可過期接受 |
| 推薦成熟 | 首次有效實付的M與台灣年度Y | 依原年名額與候選次序，不因晚審跨年改歸屬 |
| 回收／刪帳截止 | 原30天截止 | 先失去恢復資格，再安全清理；工作延遲不延長撤回期 |
| 續扣／取消 | 已確認的供應商授權及排程版本 | 變更待確認先核對；舊排程工作不能另扣一次 |
| 預告通知 | R15的7天／1天、寬限開始／截止前24小時／結束 | 過期預告不冒充未來提醒；改發適用的當前結果 |
| 檔案／暫存清理 | 引用、隔離證明及操作結算 | 不只憑createdAt或lease過期刪檔 |

掃描頻率、批量與最大可接受積壓是09／12正式配置；不把產品截止改成「下一次排程」。以事件推動加定期對帳掃描，修補漏事件；對帳只補缺失工作，不重新發明付款或資格來源。

## 07-12 每一類失敗的復原責任

DB提交前失敗保留可重試的原操作；外部成功而DB未知先查事實再補記；DB已提交而通知失敗只補通知。外部副作用前保存意圖，回應後保存參照；無法確保遠端冪等時設人工核對，不宣稱本地鎖能取消已發出的遠端請求。

交接接受與內容修改／邀請取消／到期互斥；接收容量及來源容量的帳本在同次提交結算，不以後續背景兩次各自成功拼成移轉。圖片物理清理仍獨立，跨帳戶物理去重不得誤刪另一帳戶的合法引用。

人工補處理也使用原操作與專用命令，保存判斷來源、執行者及結果；禁止直接把失敗job標成功來消除告警。通知失敗與可重建索引失敗通常不回滾業務；洩漏風險則立即停止不安全公開出口，兩者不可混為一種補償。
