# 06 身分、權限與安全

版本：2026-11-07詳細設計整合版。R08／R09、P01／P02已在02確認，本章只設計如何落實，不改產品權利。現有Bearer／所有權／交易重驗為部分基礎，並非完整安全或合規驗收。未修改程式、啟用查核或收集新證件。

## 06-01 身分與權限矩陣

| 身分／能力 | 可做 | 不可推定 |
| --- | --- | --- |
| 訪客 | 看公開、搜尋／地圖、比較、聯絡、公開文章、租補 | 不能看私有地址／草稿／證明或他人案件 |
| 登入會員 | 自己收藏／回報／帳務與私人資料 | 登入不等於查核通過、付款或管理員 |
| 內容持有人 | 編輯自己的草稿、申請發布、下架／刪除／合規恢復 | PUBLISHER不與找房互斥；不能改核准欄位、同房其他刊登或共享Property |
| 有效方案權益 | 依02開工具；接收交接全方案但須條件 | FREE不能Bot／匯入；寬限不延工具；加筆數不加GB或驗證 |
| 內容／分組管理 | 必要暫隱、核對、拆分、案件與受控更正 | 不能任意改付款、發資格或讀無關證件 |
| 帳務管理 | 對帳、核對退款與爭議、明示調整 | 不能刪交易、假造支付成功、任意收款或自動沒收 |
| 資格／查核管理 | 依授權核准贈送／查核、補件及結果 | 不自核本人利益，不把證明全公開 |
| 管理員管理 | 啟用／撤銷細分能力、MFA與緊急復原 | 不由公開註冊指定ADMIN，不與一般編輯權混用 |
| worker／外部服務 | 限單一工作及最小資源 | worker身分不是免權限，提交前仍重核最新狀態 |

每個動作依02該操作適用條件檢查帳戶生命週期、持有人、目前內容／限制、分項查核、方案工具／筆數／容量、地區及同意版本；必要下架／刪除不因滿額阻擋，私人文字編輯不套新增容量門檻。實作不能只檢查前端是否顯示按鈕或User.role。

## 06-02 登入與網站session

- 既有不透明32-byte隨機token、DB只存hash、可撤銷session及8小時預設沿用為安全基礎；沒有可信資料不能自動合併第三方帳號。帳號綁定須已登入、step-up確認及唯一對應，解綁至少留一種有效登入。
- 網站目標採同來源伺服器邊界：瀏覽器以Secure、HttpOnly、SameSite=Lax的host-only session cookie，由網站伺服器在內部轉既有Bearer；不把token放localStorage、URL、公開HTML或分享資料。這是待實作安全契約，現有login仍回Bearer、不讀cookie。
- cookie登入後需CSRF token及Origin檢查；所有狀態變更非GET。OAuth用state／nonce、支援時PKCE及精確回呼白名單，拒絕任意redirect；同Email不足以綁定。
- 密碼採Argon2既有基礎；重設token隨機、hash保存、限時一次，成功撤銷相關舊session。Email變更先確認新值再替換，不能用未驗新Email搶綁他人帳號。
- 高風險更改Email／登入綁定、付款授權、贈送核准、強制交接、刪帳、證據下載與管理員權限須近期再驗本人；MFA對管理員必要，不以另一個密碼欄位冒充。
- 具體token期限、限流、step-up時窗需在實作安全配置表列值、理由及測試；正式啟用前不得留無期限。這些是安全配置，不得改02的48h／72h／30天權益時限。

## 06-03 暫停／停權與必要權利入口

- 現有isActive會阻止一般session，尚不能滿足完整R09。目標須分一般內容能力與最小帳務／補正／申訴session，不因停權封死取消續扣／退款入口，也不為保留入口恢復全部管理權。
- P02本人暫停不自動取消原有效續扣；確認前顯示下次日期金額、明示仍扣及獨立取消入口。已取消不因恢復重啟；未取消原安排不被改期或多扣一次。
- 刪帳需驗本人、停止公開、追蹤未來續扣取消；未確認顯示處理中。撤回與恢復不復刊、不復活已刪資產或已取消授權；晚到付款／工作不繞過限制。
- 對沒有一般session者提供安全的本人核對與帳務支援，不可只憑客服收到一封Email就交出帳戶。實際查核來源與人力依E05／E06，不能假設已配置。

## 06-04 證明、私有位置與資料最少化

- Email、聯絡控制權、刊登身分、公司／證照各有狀態與適用範圍；EntitlementAccount.verifiedAt只是權益起點可信，不是任何身分通過。
- 查核證明不走公開圖片bucket／卡片路徑；最小權限、可追蹤查看／下載與到期撤銷。必要證明清單、合法用途／替代方式、保存期未核定前不對外收件，預設不要求整份身分證／產權文件。
- 公開DTO、JSON-LD、SSR資料、地圖、群組、收藏、圖片metadata、錯誤與追蹤事件均不可含隱藏門牌／精確座標及可逆識別。私有地址查詢亦須持有人或具工作必要權限，不因付費可看他人。
- 查核排隊或供應商故障不是造假；可信必要資格確定失效依02停止發布／交接及必要公開，不自設補件懲罰期限。

## 06-05 輸入、外部請求及濫用

文字長度、型別、費率及安全標記由後端白名單檢查；HTML清理與瀏覽器輸出編碼分開，不能以簡單regex宣稱免XSS。資料庫用參數查詢；排序／欄位白名單，不能把query拼成SQL。

- 圖片驗真實內容、資源／像素限制、動畫、不信檔名MIME、去GPS；SVG／任意HTML不是支援圖片。
- 只接受已核對的影片／LINE／網站連結；伺服器取外部資料須來源白名單、解析IP及重新導向重檢，不可訪localhost、內網、metadata或帶帳密URL。不新增任意外站抓取功能。
- Excel不執行公式／巨集，錯誤CSV輸出防公式注入；Bot及金流驗簽、時效／事件去重、不可把訊息userId直接當網站持有人。
- 登入、重設、驗證、回報、匯入與高成本轉圖有分帳戶／IP／操作限制，避免只按IP誤鎖共用網路。429給安全重試指引，不透露帳號存在或直接定濫用；具體閾值09／10實測。
- 憑證、cookie、查核文件、完整支付通知及私有地址不得進日誌。洩漏後撤銷／輪替並追查，不以清Git歷史假稱金鑰未曝光。

## 06-06 提交與稽核

所有敏感寫入在交易內重驗session／能力與版本，鎖順序依03；revoke與寫入序列化。管理員處置保留人、因、前後、來源與時間；需要獨立覆核或利益衝突改由他人核准的案件，無適當人力則待處理，不假造另一名管理員。系統緊急維運權限與日常帳務／證據權限分開，使用後可追溯。

完成證據：完整權限矩陣負向測試、session／CSRF／OAuth攻擊測試、跨帳戶與管理員越權、MFA與復原、證據／位置公開出口掃描、供應商驗簽、秘密輪替及帳戶限制仍能行使權利。269項舊測試不代表這套已驗證。

## 06-07 帳戶能力與分項查核決策

| 帳戶狀態 | 一般新增／發布／完成交接 | 既有私人整理 | 必要權利入口 |
| --- | --- | --- | --- |
| ACTIVE | 依各操作的查核／方案／地區／額度判斷 | 本人可管理，限制內容僅允許補正等動作 | 本人帳務、取消、退款、案件 |
| PAUSED本人暫停 | 不允許；原邀請不延長 | 依R09可整理既有內容，不因此復刊 | 仍可取消續扣／退款／恢復；不要求先恢復才能取消 |
| SUSPENDED平台停權 | 不允許 | 僅處置明許的查看／補件／安全刪除，不給完整一般權限 | 本人核對後帳務及申訴；不解除其他限制 |
| DELETION_PENDING | 不允許 | 可看撤回與可救回範圍，不能當完整編輯入口 | 截止前撤回、取消追蹤、退款／對帳 |
| DELETED | 不允許，不重建原帳戶內容 | 不可恢復已永久刪除內容 | 透過受限本人核對處理剩餘帳務／案件 |

訪客原可用功能不因帳戶受限而消失。帳戶狀態與內容限制相交取適用權限；付費、查核通過或管理員一般登入均不能覆蓋限制。

查核目標分Email控制權、聯絡管道控制權、刊登身分、公司／證照。事實狀態採NOT_SUBMITTED／PENDING／NEEDS_INFORMATION／NEEDS_REVIEW／VERIFIED／REJECTED／EXPIRED／REVOKED，核對失敗與供應商無結果分開；PENDING不等同通過也不等同造假。複查狀態與既有核准事實分開：僅待複查或供應商暫無結果，不自行撤銷仍有效的原事實；只有證據本身有期限才設EXPIRED，不加全員固定到期日。每項有效範圍綁具體值與版本，電話／公司資料變更只使受影響事實重驗。必要項失效按R08停止受影響操作；不任意撤銷其他有效項。

公開標章只說明實際核對的項目與狀態，不推論屋主產權、保證房源或信用。證明清單、驗證方式及期限必須經E05／E07具體核對才能正式收件。

## 06-08 管理能力、利益衝突與緊急處置

目標能力分CONTENT_RESTRICT、GROUP_REVIEW、VERIFICATION_REVIEW、BILLING_RECONCILE、GRANT_APPROVE、APPEAL_REVIEW、ACCESS_ADMIN及DEPLOY_OPERATOR。實際人員由12指派；同人可有數項能力，但每次操作均須範圍及工作必要性，不因帳號叫管理員就全開。

- 贈送核准不能以本人為受益者；需另一有權者。不新增「所有日常贈送必須雙簽」要求，但利益衝突不能自核。
- 申訴覆核者不得是該次原決策者；沒有第二人則待覆核，先維持必要安全狀態，不假結案。
- 首刊更正只接受可信來源、理由及更正前後值；一般編輯、匯入或直接改日期不能走此能力。
- 強制交接是受控例外：案件、明確授權與理由、目標預覽、雙方最新權利及資產檢查缺一不可；不能用資料庫直接換publisherId代替流程。
- 緊急處置可先阻止洩漏／新收款等風險；不能藉緊急模式永久取得證據下載、任意退款或自己核准贈送。使用範圍與期限、理由、後續覆核留Audit。
- 權限撤銷須在後續敏感提交中生效；已排工作也重核，不依排入時的舊管理權完成新處置。

## 06-09 安全配置與本人核對設計

| 機制 | 本輪可直接確定的行為 | 正式設定／證據 |
| --- | --- | --- |
| session | 網站cookie與後端Bearer分邊界；登出撤銷目前session，重設成功撤銷受影響舊session | 既有8小時為基礎；裝置及各入口到期測試，cookie屬後續實作 |
| 一次性確認 | 隨機token只存hash、綁用途／主體／目標值、成功消耗一次 | 時窗列安全配置，不能無期限或跨用途使用 |
| step-up | 敏感命令需要近期驗身證明，綁session／帳戶；不能由req.body傳true | 驗身方式與有效分鐘數需安全驗證後記值；不是延長訂閱／交接期限 |
| 限流 | 分帳戶、IP、操作成本；不能單靠IP判濫用或洩漏Email存在 | 09量測閾值；429與帳戶停權分開 |
| 受限本人入口 | 只核對自己的帳務／補正／申訴；令牌不能調一般內容API | 復原方式、窗口及人員列PLAN-D04；客服不得只憑自稱本人放行 |
| 稽核 | 記操作者、能力、案件、前後事實摘要與結果 | 脫敏、權限、保存列PLAN-D03；不把所有請求body記錄 |

普通登入／重設用一致對外訊息；內部可辨真因但不得回傳帳號是否存在。驗證供應商失敗不以假通過代替；安全配置缺值只阻擋依賴該能力的正式啟用，不阻礙其他規劃。

## 06-10 公開與私人資料出口清單

正式驗收需逐一檢查頁面HTML、SSR初始化資料、JSON-LD、API、搜尋索引、sitemap、圖片出口、卡片、分享metadata、錯誤回應及日誌。隱私不是只檢查畫面看不見。

訪客定位只在主動要求且同意後用於當次搜尋，不放可分享網址、廣告分析或伺服器日誌；租補填答同樣不記原值。若錯誤追蹤工具會自動抓body／URL，應在進入工具前遮蔽。公開聯絡依本人當前設定，不把登入Email或私人證明當公開聯絡來源。

私有證據下載需短期受控存取、工作必要性、Audit及撤銷；若供應商無法支援所需隔離，不啟用該證據流程。這是系統設計，未宣稱任何具體法律保存期限或供應商能力已通過。

## 06-11 單人值班的案件分流

| 案件 | 一名具權限者可辦 | 何時要換人／等候 |
| --- | --- | --- |
| 一般資格贈送 | 可依R07建案、記理由及受益人 | 操作者本人受益或有利益衝突，交其他有權者 |
| 分項查核、同房源分組 | 可依證據逐項核對；分組另需隱私同意 | 資料不足時補件或保持分開，不因排隊發標章或自動合組 |
| 申訴覆核 | 可由未參與原處置的有權者處理 | 原處置者不得覆核本人決定；無替代者保留案件及通知 |
| 退款 | 留下有效申請時間、來源、案件狀態與對帳證據 | 依C04鎖定權利；內部排隊不改起算或縮減可退額，付款結果未知先查原交易 |

對外開放前由營運記名指定主要及備援、能力範圍與可接案時段，演練原處置者迴避、備援離線、逾期提醒及交班。每週檢查待辦數、最老案件與可用工時；超出能力先調低新增邀請速度，既有退款、申訴與取消入口持續可用。不在未量測前承諾固定時效。
