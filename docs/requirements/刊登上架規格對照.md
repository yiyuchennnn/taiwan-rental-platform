## 本批程式範圍

`checkConfirmedPublicationRules` 是網站／Bot／匯入未來可共用的純檢查器，未連接公開 API，也不寫入資料庫。

已實作：

- 02-06：至少一種非空白聯絡管道；四種費用計法不能 null。
- 02-06：照片張數 3～30、恰一封面，每張須關聯具展示圖、縮圖及 GPS 處理時間的資產。這只檢查處理紀錄存在，不驗證檔案內容或網址可達性，也不要求已量測位元組才能通過這項局部檢查。
- 02-09：SUSPENDED / BLOCKED 不能通過平台限制檢查。
- 回傳錯誤代碼、欄位路徑、企劃章節；不回傳地址、聯絡資料或照片網址。
- 即使上述通過，仍明列 outstandingChecks；沒有 canPublish 或狀態轉換能力。

不直接將此函式結果當成上架授權。輸入為伺服器已載入、型別正確的資料，不是 HTTP 輸入驗證器；公開 API 未建立前，不新增對外契約。未修改 schema、migration、登入 API 或既有資料。

## 完整上架服務仍須完成

1. 依型態條件驗證完整內容；未決矩陣不能以任意預設補齊。
2. 驗證登入者及管理權、帳號狀態、Email／聯絡／刊登資格；不把 RENTER 和 PUBLISHER 當互斥用途。
3. 重新讀取平台限制與目前狀態，避免舊資料快照繞過限制。
4. 在同一交易中檢查公開額度並更新狀態；公開已滿保留草稿，下架不可被封存額滿阻擋。付費權益來源及 C01 等衝突尚未完整實作。
5. 同一交易處理首次成功上架時間；不得更動既有首次時間或猜測回填歷史值。
6. 驗證原圖格式、大小、使用權與圖片處理結果；MediaAsset 的 displayBytes 不是原檔大小，不能拿來替代 10 MB 原圖檢查。
7. 確認公開地址與分組流程；嚴禁直接序列化完整 Property／精確座標／內部資料給訪客。

- 刊登只需填坪數，可估算；目標為本次出租範圍室內使用面積，不含共用公設，套房／雅房不得填整戶面積。

- 共用檢查器新增住宅型態與正數坪數檢查；不對草稿施加完整性要求，不改資料庫可空白設定。
- 歷史 rentalType 是自由文字，新檢查器不擅自翻譯或覆寫；不識別的值於上架檢查回報待選擇，草稿／既有資料仍保留。
- 建物選項與部分條件必填已於下一節確認，不從面積簡化推論其他欄位全部選填。儲存轉換同步整棟型態與 isWholeBuilding；尚未開放上架 API。

| 操作順序 | 基本資料 → 費用與設備 → 照片與聯絡 → 預覽上架；隨時存草稿，上架前集中缺項且可定位欄位 |

### 本批交付界線

- listing-options.ts 提供建物與共用空間選項。
- publication-details.ts 提供上述結構化分區驗證，包含押金／管理費的互斥填法、真實日期、樓層範圍、整棟一致性及各型態的空間規則。欄位路徑可供未來畫面定位錯誤。
- 此 schema 只用於上架分區，不用於草稿儲存；不設預設答案、不把缺值轉成零、不以獨立分區驗證冒充完整上架資格。
- 原 checkConfirmedPublicationRules 仍負責聯絡、坪數、費用計法、照片與平台限制等既有局部檢查；兩者尚未由完整上架服務協調，不能單獨授權公開。
- 尚無刊登前端；草稿新增／讀取／PATCH 與私有地址副本已實作，圖片 API 核心也有隔離驗證但正式上傳未啟用。完整上架服務仍未完成。欄位 mapping 詳見 docs/database/刊登輸入模式儲存與驗收.md；正式資料庫未操作。
