# 現有資料模型對齊與驗收

> 2026-11-06狀態註記：下文保留該批歷史規格／驗收事實，不能當作現行產品基準或最新全量測試。最新依行政資料01／02與 [目前進度](../../行政資料/進度與待辦/進度執行表.md)；套房合併、免面積來源、舊C01及無限公開等過往決策若與新版R02／02-01／02-09衝突，均已被取代。新欄位、完整上架與正式容量尚未全部接妥。

依據：根目錄 `01_需求與版本範圍.md`、`02_商業規則與狀態.md` v0.1。
本批只處理現有 User／Property／Listing／ListingMedia 的資料基礎與測試，不等於整個首發模型或後端流程完成。未修改兩份企劃。

| 02-09 | TRASHED、trashedAt；archiveReason 區分 MANUAL/RENTED/QUOTA_EXCEEDED | 草稿／公開／封存與平台限制分開。回收區要求刪除時間；封存原因不可掛在草稿或公開上。舊 UNPUBLISHED 保留，不猜測轉換原因；狀態服務、額度、30 天清除工作未實作 |
| 02-07 | exactAddressConsentAt，預設無同意 | 僅保存明確選擇，不等於付費權益或公開資格。概略位置精度、公開 DTO、搜尋隱私、重新定位與公開版待確認編輯尚未實作，不能直接把完整 Property 序列化給訪客 |

## 遷移與資料保護

新增兩個 migration，未修改歷史 migration：

1. `20261101000000_extend_confirmed_enums`：擴充舊 enum。需獨立提交，避免同交易使用剛新增 enum 值。
2. `20261101000100_align_confirmed_listing_models`：其餘變更在交易內執行。保留既有欄位／資料，沒有 DROP TABLE、DROP COLUMN 或猜測式資料回填。

本批未連線或遷移專案既有資料庫。**尚未完成正式部署前的實際資料盤點與備份／還原演練，不能直接視為正式環境可執行。**

執行前至少查核：

- 舊圖片是否同一刊登已有多個 isCover=true；不得自動替使用者選封面。
- 舊 rent/deposit 是否有負數。本批會拒絕不符合完整性約束的舊資料，不自動清洗或刪除。
- 舊 publishedAt／UNPUBLISHED 實際語意；本批保留原值，須另提可核對回填方案。
- 歷史重構 migration 曾刪除舊 Property 欄位；本批不修改已存在 migration，也無法恢復當時可能已遺失的資料。

若第二個 migration 失敗，該交易中的表欄位／索引等變更回滾，既有資料保留；第一個 migration 已提交的 enum 擴充仍保留。正式使用 Prisma 部署後的失敗紀錄處理另需部署手冊，不應盲目重跑。

CHECK、部分唯一索引與 trigger 是 SQL migration 管理的約束，Prisma schema 無法完整表達。後續不可只靠 db push 重建資料庫。

## 測試執行與範圍

執行：`npm test --workspace=@rental/api`。

前提：本機 PATH 有 PostgreSQL 的 initdb、pg_ctl。測試使用既有 pg 與 Vitest，無新增套件；不可用 root 執行 initdb。缺工具時測試會失敗，不跳過並假裝通過。

測試自己建立 OS 暫存目錄與 PostgreSQL cluster，只開該目錄的 Unix socket、不開 TCP、不讀 .env／DATABASE_URL；結束關閉並清除暫存環境。先跑歷史 migration，再放入既有資料樣本，最後套用本批 migration。

覆蓋：

- 舊會員、刊登、房屋地址、地下樓、圖片保留，首次時間不猜測回填。
- 僅有刊登者的草稿可保存並先收照片；未填／明確沒有／費用包含不混淆。
- 授權者與原房屋建立者分開；房源聯絡資料獨立保存。這不是跨帳號 API 權限測試。
- 首次上架時間寫入後不可因修改、封存、重新上架而更改或清空。
- 回收區時間一致性；恢復狀態不會順便清掉既有平台限制。
- 負值拒絕、兩個連線同時選封面僅一個成功。
- 圖片仍有其他引用時不可刪除，刪刊登不連帶刪共用資產。
- 真實資料庫欄位與 Prisma 模型的型別／可空白性逐欄比對；實際 Prisma Client 可建立及讀取新舊資料。
- 舊多封面資料使 migration 失敗時，確認資料保留且第二批 schema 變更回滾。

這些是資料層測試，未驗證 UI、完整 API、身分驗證、額度併發、地圖、付款或外部圖片儲存，也未驗證正式庫效能。

## 本批未完成與建議討論

1. **選項與條件必填矩陣**：依使用者確認，先建欄位；建議後續列一份「出租型態 × 必填欄位 × 允許選項」表，再做網站／Bot／匯入共用發布驗證，不能現在自行決定。
2. **歷史首次時間**：依使用者確認保留舊資料待核對；建議有可信紀錄才回填，無法核對的資料明示未知，排序例外另討論。
3. **地址待確認編輯**：目前仍只有現行 Property。建議後續以獨立待確認變更記錄保存新地址／樓層／房號／型態，確認定位與分組後才更新公開版本；欄位選項及審核流程尚未定義，這批沒有冒充已支援。
4. **公開地址隱私**：僅加同意紀錄。建議先定概略位置產生方式、精度及失敗策略，再實作只輸出白名單欄位的公開資料介面；不得先用任意固定偏移量當成定案。
5. **管理權與帳號雙重用途**：資料已能分別指向房屋建立者、刊登管理者；現有 role 保留相容。建議後續一般會員共用找房能力、刊登權由驗證資格判斷、管理員權限另分；尚未實作，需配合 06 文件。
6. **圖片生命週期／容量**：模型已容納引用及實際大小，沒有 GB 值；方案容量、同資產多引用歸戶、滿容量換圖、儲存刪除失敗補償及案件留存需後續確認。
7. **新增其他首發模型與服務**：文章、品牌、訂閱、退款、通知等均不在本批。下一批建議先完成刊登狀態／額度與上架共用驗證，再接公開搜尋 API；不要把現在可空白的草稿直接公開。
