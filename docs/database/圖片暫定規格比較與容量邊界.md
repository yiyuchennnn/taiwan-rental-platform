# 圖片暫定規格比較與容量邊界

日期：2026-11-03（台灣時間）。使用者已暫定同意 1920px 展示圖、480px 縮圖、WebP 品質 82、不放大小圖、單張原始輸入上限 10,000,000 bytes、動畫暫不接受。此決策已回寫 02 企劃的修訂紀錄，沒有填入各方案 GB。

## 本批完成

- `image-profile.ts` 固定暫定值，runtime 及量測腳本共用；舊環境值若與暫定值衝突會明確失敗，不悄悄套用其他尺寸。上傳旗標仍關閉，容量來源缺失仍拒絕上傳。
- `compare-images.ts` 本機離線產生 1920／2560 對照與實際 bytes，並可讀取使用者授權的本機照片目錄。預設自行產生三組合成圖；無憑證、無資料庫、無 R2 請求，不把原圖上傳或寫回來源目錄。
- `storage-capacity.ts` 以 BigInt 計算 80% 提醒、100% 停止新增、預留大小、最後位元組、降級超額；未知上限或大小一律 UNKNOWN／不放行。此為純運算核心，不是完成正式計量來源、帳務歸屬或通知寄送。

## 比較結果及限制

本機結果：`/workspace/image-validation-20261103/comparison.html`（圖像內嵌，離線可開啟）及同目錄 `measurements.json`；每張圖的展示圖、縮圖也有獨立檔案。原量測時產物在 checkout 外；後續依使用者授權交付 GitHub，已將 PNG／PDF／WebP／量測 JSON 納入 docs/reports/image-comparison-20261103，未納入內嵌大量 base64 的 HTML。

以下數值是展示圖＋縮圖的實際 bytes，不包含原圖、reservation metadata 或其他服務成本。

| 合成測試圖 | 1920px 組 | 2560px 組 |
| --- | ---: | ---: |
| 明亮漸層 | 29,860 | 43,560 |
| 細節線條與紋理 | 199,950 | 647,920 |
| 暗部雜訊 | 646,954 | 1,478,286 |

兩組縮圖同為 480px、品質參數 82；展示圖不裁切、不放大。輸出經核心處理去除 metadata。工具中的像素上限 40,000,000 與處理 timeout 15 秒只是此量測工作使用的資源限制，不是已確認的正式伺服器資源規格。

困境：專案沒有代表性房源照片。合成圖證實雜訊與尺寸會顯著影響結果，但不能證明真實室內照片平均占用或主觀清晰度，也不能用三個樣本平均來決定會員 GB。

建議方案：由使用者提供有權使用的照片，包括明亮室內、暗處、磁磚／窗框／文字細節；先以 3～5 張試跑，正式估算再增加不同手機與光線的樣本。替代方案是維持合成驗證，延後正式畫質／GB 決策；不能把合成圖片包裝成真實成本證據。不要使用含私人內容的對話截圖作為房源樣本。

再次產生合成比較（輸出目錄必須不存在，避免覆寫）：

```sh
npm run compare:images --workspace=@rental/api -- --output /workspace/new-image-comparison
```

用授權照片目錄比較：

```sh
npm run compare:images --workspace=@rental/api -- --output /workspace/authorized-image-comparison --input-dir /path/to/authorized-photos
```

來源支援 JPEG／PNG／WebP、單檔不超過暫定上限，每次 1～30 張；不跟隨目錄內的符號連結。來源檔名會進入報告，真實照片報告可能包含私人內容，應自行控管分享。

## 容量來源接入條件

可信來源須提供上限、已用、預留三者；CLEANUP 在遠端刪除確認前不能提前釋放，PENDING 不得漏計或在 attach 時重複計。上傳前以 incomingBytes 計算，已預留的接入交易以 0 再檢查。所有讀取與預留仍需帳號交易鎖；純函式本身不建立鎖。

未知舊圖片大小、共用資產跨會員的容量歸屬、各方案 GB 仍未完成決策／對接，不臆測。80% 只產生判斷結果，尚未接 UI 提醒或通知事件；100% 換圖仍屬 C12，沒有以刪舊圖再上傳方式繞過。
