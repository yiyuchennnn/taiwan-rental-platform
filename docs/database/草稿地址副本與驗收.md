# 草稿地址副本與驗收

依據：02-06 草稿允許缺資料、02-08 各刊登者內容／管理權分開、02-09 地址改動需確認。此批只完成 DRAFT 地址工作副本，不實作公開地址變更核准、定位或分組。

## 設計

- 新增一對一 DraftAddress：縣市、行政區、路街門牌、房號、社區皆可空白。樓層仍使用 Listing 的已確認單層／範圍／整棟欄位，不再新增一套副本樓層。
- 不完整地址不建立 Property、不使用假地址，不自動將不同刊登合併。
- 未有副本且有既有 Property 時，只有該草稿管理者可從 GET 看目前連結地址，標示 LINKED_PROPERTY；不返回 Property id、建立者或精確座標。
- 第一次編輯時複製該連結的地址文字到私有副本後套用 PATCH；不修改 Property，也不讓其他刊登者看到變更。
- 只有私人管理路由可讀寫，沿用交易中管理權／狀態／有效憑證檢查。非 DRAFT 拒絕，不直接對公開內容編輯。

## API 語意

POST／PATCH /api/v1/drafts 的 body 新增 address，可為欄位物件或 null。例如：

```json
{"address":{"cityCode":"63000","districtCode":null,"addressLine":"待補門牌","roomNumber":null}}
```

- 缺少 address 不變；address:{} 不變且不更新時間。
- 子欄未提交保留；null 明確清空該欄。address:null 建立全空副本，表示刻意清空目前草稿地址，不能重新顯示舊 Property 地址。
- 改縣市但未提交行政區時清空原行政區，避免相同代碼被誤解為新縣市另一區。路街文字不擅自改寫或猜測。
- 已填縣市代碼必須存在；已填行政區必須存在，有縣市時必須屬於該縣市。只有行政區尚缺縣市可暫存，但不是完整可發布地址。
- 不依 City.isEnabled 限制私人草稿，營運開放地區與發布條件仍需後續處理；不自行決定首波地區。
- 回應 addressSource 為 NONE、LINKED_PROPERTY 或 DRAFT_COPY；address 為 null 或五個地址欄位。無任何公開定位或門牌公開承諾。
- 禁止由前端提交座標、Property／Listing 識別碼或關聯操作來繞過管理權。

可行方向：由上架服務在資料完整後執行定位及核對，再決定建立／連結房屋；不明或衝突則保留草稿。自動合併信心門檻及人工拆組仍依 C09 待決，不能在本批自行設定。修改公開房源的待確認記錄需獨立設計，不等同這次 DRAFT 副本已支援。
