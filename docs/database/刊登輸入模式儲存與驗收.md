# 刊登輸入模式儲存與驗收

依據：`docs/requirements/刊登上架規格對照.md` 的後續確認。

## 變更

新增 `20261102000000_add_listing_input_modes`，只加欄位及 CHECK 約束，不改歷史 migration、不刪除或回填既有資料。

| 資料 | 新欄位／對應 |
|---|---|
| 其他住宅說明 | buildingDescription |
| 押金選擇 | depositMode、depositMonths；固定額使用 deposit |
| 管理費選擇 | managementFeeMode；另計金額使用 managementFee |
| 入住選擇 | occupancyMode；指定日期使用 availableFrom |
| 刊登樓層 | floorMode、floorFrom、floorTo；不改共用 Property.floor |
| 陽台使用 | balconyMode；已知專用數量使用 balconies |
| 共用空間 | sharedSpaces、sharedSpaceDescription |
| 設備確認 | equipmentMode 搭配既有 furniture、appliances、equipmentConfirmedAt |

新模式預設 null；sharedSpaces 為空陣列，不單獨當成已確認無共用空間。歷史金額、日期、樓層、面積類型全部保留，不從零元或舊資料猜測模式。草稿仍可只存在刊登者。

儲存對應由 publication-details-storage.ts 提供：

- 完整分區更新先通過 publicationDetailsSchema；不是草稿 PATCH，也不是可直接公開的輸入。
- 月數押金不自行換算成固定金額；免押金明確存 0。含租管理費存模式，金額留空，不與無管理費混淆。
- 日期用 UTC 零時保存 SQL DATE；隨時入住清除指定日期。
- 整棟型態同步 isWholeBuilding；樓層不寫回共享 Property，避免改動其他刊登者的資料。
- 模式切換清除舊依賴值；沒有任意 spread 使用者輸入，不接受 status、publisherId 或權限欄位。
- 讀回以明確模式組成分區；資料不足回 complete:false 與欄位問題，不補預設答案，不修改原始列。
- areaType 與坪數不在此分區更新範圍，不重新詮釋舊面積。

## 未完成

沒有新增刊登／草稿 HTTP API、前端表單、登入工作階段、資格審核、額度交易或公開地址介面。新模式只完成儲存基礎，完整上架服務仍需整合所有檢查與管理權限。

後續草稿 PATCH 必須採允許缺項的驗證，不可套用本次完整分區 schema；讀回不完整結果須保留原始資料供編輯，不可清空舊資料。公開 API 不可直接輸出內部完整 Listing／Property。
