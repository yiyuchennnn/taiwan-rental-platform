# 登入工作階段與刊登管理權基礎

依據：01-01、02-11。此為內部技術決策，不增加付費政策、刊登資格或帳號生命週期規則。

## 選擇與理由

- 使用 32 隨機位元組的 opaque Bearer Token，每次登入建立新工作階段；資料庫僅保存 SHA-256 digest。相較無狀態 JWT，可直接撤銷並支援後續裝置管理，不依賴第三方服務。
- Token 只於登入回應傳回一次，不存原始值、不寫入 URL 或日誌。受保護請求以 Authorization: Bearer 傳送，伺服器不信任 userId／publisherId／X-User-Id。
- 不使用 Cookie，因此本批未引入跨站 Cookie 認證；前端不得擅自改成 Cookie，也不把本批當成 Cookie CSRF 防護完成。正式環境必須 HTTPS，Token 前端保存方式待 05／06 與前端整合，建議記憶體保存，不預設持久化到 localStorage。
- SESSION_TTL_SECONDS 為正整數秒，預設 8 小時，屬可調整安全設定，不是承諾記住登入多久的產品政策；無 sliding refresh、自動續期或 remember-me。正式環境須於 06 明確核對設定。
- 每次受保護請求查詢撤銷／到期／目前帳號 isActive，無效統一 401。停用後請求立即拒絕，但完整停用／恢復／撤銷所有裝置的生命週期尚未建立。
- 刊登管理權按當下 publisherId 判斷，外人與不存在統一 404，不自動授予 ADMIN 管理所有刊登；房屋建立者不等於刊登管理者。
- middleware 是讀取前的門檻，不是未來寫入的唯一防護。後續草稿更新／交接必須在交易或更新條件中再次限制 publisherId 與狀態，避免檢查後管理者變更的競態。

## API

| API | 行為 |
|---|---|
| POST /api/v1/auth/register | 保留既有註冊行為，不直接發工作階段 |
| POST /api/v1/auth/login | 保留 data.user，新增 data.accessToken、tokenType、expiresAt；不回密碼雜湊或 session digest |
| GET /api/v1/auth/me | 有效憑證回目前會員；無效 401 |
| POST /api/v1/auth/logout | 撤銷目前工作階段，成功 204；已撤銷憑證不能繼續使用，其他裝置不受影響 |

認證回應 Cache-Control: no-store；資料庫或內部錯誤不對外序列化堆疊。未在產品公開新增測試用刊登路由；管理權 middleware 只在測試路由驗證，待後續草稿 API 串接。
