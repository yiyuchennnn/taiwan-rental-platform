# 正式圖片儲存服務比較

資料查核：2026-11-02（台灣時間）。本文件是候選比較，不是供應商決定、報價或對外服務承諾。沒有替使用者開通或購買任何服務。

## 平台需求

既有架構為 Express／Prisma／PostgreSQL，自有 Bearer 工作階段。草稿圖片不可因放進公開 bucket 而被任何人取得；公開圖片需由房源狀態及權限決定曝光。需能追蹤展示圖／縮圖實際容量、引用、刪除及失敗補償。原圖處理後不長期保存。

目前圖片核心在後端自行產出 WebP 展示圖／縮圖。儲存服務主要負責物件保存與存取，不必同時購買供應商圖片轉換功能；後續若採轉換服務，需另驗證 GPS、成本與功能，不能重複付費卻假設規格等價。

| 候選 | 與現有架構的整合 | 草稿保護方向 | 費用核對重點 | 選擇條件 |
|---|---|---|---|---|
| Cloudflare R2 | S3 相容 API，可保持現有登入與資料庫 | 私有 bucket，後端授權後簽名讀取或代理；不可直接把草稿放公開網域 | 儲存、Class A 寫入／列舉、Class B 讀取；官方 R2 網際網路 egress 不收費，但相關 Workers／網域／其他服務不因此全部免費 | 適合先評估獨立圖片儲存與讀取成本；仍需實際驗證權限及部署 |
| Amazon S3 | 維持現有架構，使用 IAM／bucket policy 與 S3 SDK | Block Public Access、私有物件與受控讀取；若用 CDN，另配置存取與快取策略 | 按區域、儲存類別、請求與資料傳輸等核價；CDN 等服務另算 | 若部署或維運已有 AWS 能力，可優先考慮；本次未取得現行價格，不填估算單價 |
| Supabase Storage | 儲存 API 與 RLS 整合；目前自有 Token 不是 Supabase Auth JWT，不能直接假設 auth.uid() 可用 | 可由後端檢查現有會員管理權後使用服務端操作，或另設整合；服務 key 不可交給瀏覽器 | 需按所選專案方案及儲存／流量等用量核對，不假設免費方案足夠 | 若後續本來要用 Supabase 生態系有整合價值；不為了圖片就擅自遷移帳號或資料庫 |

## 可核實的 R2 Standard 費用資料

本次讀取 Cloudflare 官方文件的 production 原始碼：

- 儲存 US$0.015／GB-month。
- Class A：US$4.50／百萬次；Class B：US$0.36／百萬次。
- Standard 每月免費額度：10 GB-month、Class A 100 萬次、Class B 1,000 萬次；不適用 Infrequent Access。
- R2 的 Internet egress 免費；計費單位有進位，不能只拿平均用量乘單價當最終帳單。

以上是查核時官方文件所載美元價格，不含其他服務、稅額、匯率或未來調價，不是整個租屋平台的固定月費。供應商免費額度也不等於本平台每會員免費方案的 GB 配額，後者企劃尚未定。

R2 官方另明示：S3 presigned URL 使用 R2 S3 API 網域，不能直接當作自訂網域的簽名機制。正式方案必須選擇適合的授權讀取／公開快取架構，不承諾換個網域就可保護草稿。

## 如何比較實際月費

需要展示圖＋縮圖的實際平均大小、資產數、回收區／證據保留量、每月上傳／瀏覽次數、快取命中與部署區域。以測試實際輸出取樣後，分開估算：

1. 保存容量（含仍有引用及回收區內容）。
2. 寫入、讀取、列舉及刪除的請求成本。
3. 對外流量、CDN、授權代理／函式執行成本。
4. 備份、監控與維運成本。

沒有上述用量前不提供保證月費或宣稱哪家一定最便宜，也不先填各會員方案 GB。

## 建議

以目前保留自有登入／API 的架構，可先評估 R2，再以預計部署地區的 S3 報價作對照；若之後確定採用 Supabase，則重新比較整體整合成本。這是技術評估次序，不是已選定供應商。

選定後仍須安全驗證：私有草稿、未授權下載拒絕、下架後存取／快取策略、URL 有效期、憑證最小權限、物件寫入與資料庫交易失敗補償，以及刪除引用與容量同步。
