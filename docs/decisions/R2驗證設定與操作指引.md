# R2 驗證設定與操作指引

使用者已選擇 R2 作為第一個正式儲存驗證候選，並在負責人帳號建立驗證 bucket 與憑證，尚未選定為正式上線儲存。此文件不授權公開 bucket 或購買其他服務。

已建立 R2 私有驗證 adapter、實際 AWS S3 SDK 簽名／序列化測試及手動遠端驗證指令。新增 13 項本機測試，共 190 項全部通過，型別檢查、編譯與 diff 檢查通過。

本機 190 項測試與遠端驗證分開記錄。2026-11-02 使用者發布設定並授權驗證後，真實 R2 驗證成功（指令 exit 0）：自行產生圖片的展示圖與縮圖上傳、內容逐位元讀回比對、60 秒簽名 GET，以及未簽名 S3 GET 拒絕均通過；清除三個驗證物件後逐一 HEAD 確認 404。未修改 bucket 公開設定。使用者截圖顯示無自訂網域、公開開發 URL 停用。

初次遠端測試在未簽名讀取判斷失敗：R2 回傳 HTTP 400 / InvalidArgument，內容指出認證問題；原腳本僅接受 401/403/404。已補入限定此錯誤代碼且訊息包含認證識別的 400 判斷，並加入安全步驟標記與狀態碼日誌，不輸出完整回應、金鑰或簽名網址。失敗批次均執行 finally 清理且無清理失敗訊息；最終成功批次額外逐一確認物件不存在。型別與 diff 檢查通過。這不是正式圖片功能或全平台上線驗收。

## 使用者建立驗證資源

1. 登入 [Cloudflare Dashboard](https://dash.cloudflare.com/)，前往 R2 Object Storage。官方文件說明啟用 R2 後才能建立其 API Token；若要求付款資料或訂閱，使用者須先看清楚費用條件，不是整個平台永遠免費。
2. 建立專門測試的 bucket，例如 `taiwan-rental-r2-validation`。不使用既有正式圖片桶、不連接公開網域。預設私有；確認 Public Development URL（r2.dev）與自訂公開網域沒有啟用。其他區域／法域設定僅為驗證環境，不當成正式資料落地政策。
3. 在 R2 頁面 Account Details → API Tokens → Manage，建立 R2 API Token。選 Object Read & Write，限定剛建立的單一 bucket，不選 Admin Read & Write 或所有 bucket。
4. 安全保存產生的 Access Key ID 與 Secret Access Key。Secret 通常只顯示一次，不貼到對話、截圖、Git 或文件。
5. 從 R2 面板取得 S3 API endpoint（如 `https://<account-id>.r2.cloudflarestorage.com`）及 bucket 名稱。這兩項不是金鑰，可以提供給協作者以準備精確網域白名單。

如果 bucket 帶有 jurisdiction，使用面板實際提供的對應 endpoint（default／eu／us／fedramp），不自行改寫 account-id 或法域。

## 伺服器環境設定

已在環境草稿新增以下需求名稱，沒有填入任何憑證值：

| 名稱 | 用途 |
|---|---|
| R2_ENDPOINT | 實際 S3 HTTPS endpoint |
| R2_BUCKET | 驗證用 bucket 名稱 |
| R2_ACCESS_KEY_ID | S3 簽名 Access Key ID，由使用者安全提供 |
| R2_SECRET_ACCESS_KEY | S3 簽名 secret，由使用者安全提供 |
| R2_VALIDATION_PREFIX | 預設 rental-validation，所有驗證物件都在此前綴 |

必須使用伺服器可實際讀取的受保護環境值。SigV4 在本機計算簽名，不能使用僅在 HTTP proxy 替換的 placeholder 來當 secret；不要把一般 Cloudflare REST Bearer token 當 S3 Secret Access Key。

網路白名單要加入實際 endpoint 的完整 hostname，保留既有網域；目前因 endpoint 未提供，沒有猜測或擴大白名單。設定草稿保存不會立即執行或套用；依環境設定流程儲存／發布後才重查實際可用性。這不是把網站公開上線，代理不自行發布。

## 遠端驗證指令（已完成一次完整成功驗證）

在上述設定、安全值與精確網路權限齊備後，於專案根目錄執行：

```sh
R2_RUN_REMOTE_VALIDATION=1 npm run validate:r2 --workspace=@rental/api
```

此指令會在指定 bucket／prefix 下寫入一組很小的自行產生測試圖及 reservation，讀回比對兩張圖、測試短時簽名 GET、確認未簽名 S3 GET 被拒絕，再刪除並逐個確認物件不存在。這會產生少量 R2 請求，不建立／刪除 bucket、不修改公開設定、不使用真實房源照片。

未設 `R2_RUN_REMOTE_VALIDATION=1` 即停止，不猜測憑證或啟用外部寫入。不得把未執行／被阻擋的檢查記成通過。在受限執行沙箱內，tsx IPC 可能需要受支援的執行升權，不可藉關閉代理或 TLS 驗證繞過。

日誌不輸出 credentials、Authorization、SDK stack 或 presigned URL；失敗僅輸出安全錯誤碼，待清理時列出內部驗證前綴／UUID 以便核對。

未簽名 S3 endpoint 拒絕不代表所有公開自訂網域也已被稽核；仍須使用者在 Dashboard 確認 bucket 未啟用公開入口。

## Adapter 的保障及限制

- 使用 HTTPS 與繼承的 proxy／CA；只接受帳號專用的 R2 endpoint，不會借用 AWS_PROFILE 或 instance role。
- 使用 path-style／region auto，固定 SDK 版本；maxAttempts=1，避免條件寫入回應遺失後的自動重試被誤認為確定失敗。使用 R2 已列支援的 Content-MD5、If-None-Match 與私有 Cache-Control，不設定 public ACL。
- 每個驗證資產以 reservation nonce 記錄保留所有權。寫入使用條件式避免覆寫；清理前確認 metadata nonce，只處理三個固定鍵，不列舉或刪除任意 prefix。
- 回應遺失時先回報結果不明，須查核 marker metadata 才可確認所有權。沒有證據時不刪除。
- 所有權證明目前只在 adapter instance 記憶體中，程序重啟後不做自動刪除。正式流程須把 recovery／nonce 寫入持久化工作紀錄，否則只能人工核對驗證資源。
- 讀回／簽名不是管理權檢查；尚無公開下載路由。真正接入時仍須以刊登身分、狀態及權限授權，不能讓前端提交任意 assetId 取得簽名。
- 簽名 URL 是短時 bearer link，持有者在有效期內可使用；它不會隨登入登出自動撤銷。正式有效期／快取／下架處理尚未定案。
- 尚未整合 MediaAsset、ListingMedia、會員容量／引用計數、上傳 HTTP、任務重試及正式付費驗證。不得將驗證 adapter 標為完整圖片功能上線。
